1. Executive Summary & Objective

This project delivers an automated, production-grade Continuous Integration and Continuous Delivery (CI/CD) pipeline for a microservice-oriented Calculator REST API. Developed for CSE 816, the system eliminates manual deployment risks through a fully trigger-driven pipeline that ingests code changes from GitHub, enforces compilation and automated test suites (JUnit 5 + MockMvc), builds secure multi-stage Docker images, pushes versioned artifacts to Docker Hub, and orchestrates zero-downtime multi-container deployments via Docker Compose fronted by an Nginx reverse proxy.

3. Jenkins CI/CD Pipeline Stages Breakdown

Stage 1: Checkout & Stage 2: Build Source & Packaging

Triggered automatically via GitHub webhooks (fallback: SCM polling every 5 minutes). Checks out the target commit, logs Git metadata, and executes mvn clean package -DskipTests -B to compile Java 17 bytecode and package the executable fat-JAR. Jenkins archives the generated JAR for release auditing.

Stage 3: Automated Test Suite & JUnit XML Reporting 22/22 Tests Passing

Runs mvn test -B across 13 CalculatorServiceTest unit tests and 9 CalculatorControllerTest MockMvc integration tests. Ingests Surefire XML reports into Jenkins via junit 'target/surefire-reports/*.xml'. Pipeline fails immediately if any test fails, blocking bad builds from containerization.

Stage 4: Multi-Stage Docker Build Minimal Attack Surface

Builder Stage: maven:3.9.6-eclipse-temurin-17-alpine utilizes layer caching by running mvn dependency:go-offline before source compilation.
Runtime Stage: eclipse-temurin:17-jre-alpine slashes image footprint from >700MB to ~180MB. Security is enforced by provisioning a dedicated non-root user (appuser:appgroup) and locking down file permissions. Tagged dynamically with both ${BUILD_NUMBER} and :latest.

Stage 5: Secure Docker Hub Push Registry Integration

Uses the Jenkins Credentials Store (dockerhub-creds) via withCredentials. Authenticates securely using standard input piping (docker login -u "$USER" --password-stdin) to avoid exposing secrets in logs. Pushes both immutable build tags and :latest, followed by immediate docker logout.

Stage 6: Orchestrated Deployment & Health Verification Idempotent Deployment

Launches the multi-container stack via docker compose down --remove-orphans && docker compose up -d --force-recreate. Actively polls http://localhost/actuator/health until the Spring Actuator status is "UP" (up to 20 attempts). Performs an automated end-to-end smoke test on /api/v1/add?a=10&b=20 through Nginx.

5. Technical Challenges Faced & Engineering Solutions

# Challenge Encountered Root Cause Analysis Engineering Solution Implemented
1 Source code compilation failure (\ufeff illegal character) Windows text editors silently injected a UTF-8 Byte Order Mark (BOM) at the start of Java source files, violating Java compiler specifications. Developed and executed an automated Python BOM-stripping routine across all files in src/, establishing clean cross-platform UTF-8 encoding.
2 Premature container health probe failure on startup Spring Boot JVM warm-up and Tomcat initialization require 15–20 seconds, causing immediate Docker health checks to fail and trigger restart loops. Configured start_period: 30s, interval: 15s, and retries: 3 in both Dockerfile and Compose, allowing JVM warm-up before monitoring.
3 Container permission denied on non-root execution Running as non-root user (appuser) failed because the application JAR and runtime directory were owned by root during multi-stage copy. Added explicit non-root group/user provisioning and applied RUN chown -R appuser:appgroup /app prior to invoking USER appuser.
4 Idempotency & container naming collision in Jenkins Consecutive Jenkins pipeline runs crashed due to existing container name conflicts and lingering orphaned networks. Implemented pre-launch teardown (docker compose down --remove-orphans) and forced recreate flags (--force-recreate) in the Deploy stage.
5 Secure credential management for Docker Hub Hardcoding Docker registry passwords in repository Jenkinsfile exposes security credentials and violates DevSecOps standards. Configured Jenkins Credentials Store (dockerhub-creds) combined with withCredentials and piped password via --password-stdin.

8. Conclusion & Capstone Project Roadmap

This mini-project demonstrates the practical realization of continuous integration and continuous deployment principles. By decoupling the stages into modular, reproducible automated steps, developers can focus on feature development while guaranteeing that every pushed commit is rigorously compiled, tested, containerized, and deployed into a resilient multi-container runtime.

This automated architecture forms the direct engineering foundation for the end-of-semester Capstone project, which will expand this calculator microservice with Ansible automation, Kubernetes cluster management (Pods, Services, Ingress, HPA), and Prometheus & Grafana monitoring dashboards.
